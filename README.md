1. Пользователь и группа
Был создан пользователь student2 и группа developers.

Пользователь student2 был добавлен в группу developers.

Проверка:
groups student2

2. Общий каталог
Был создан каталог:

/srv/shared

Владелец каталога:
root

Группа каталога:
developers

Права каталога:

drwxrwxr-x

Это означает:

владелец root имеет права чтения, записи и выполнения;
группа developers имеет права чтения, записи и выполнения;
остальные пользователи имеют права чтения и выполнения, но не имеют права записи.
3. Проверка создания файла
От имени пользователя student2 был создан файл:

/srv/shared/student2_file.txt

Команда:

touch /srv/shared/student2_file.txt

Файл был успешно создан, потому что student2 является членом группы developers, а группа имеет права rwx на каталог /srv/shared.

4. Попытка удаления файла
От имени основного пользователя была выполнена команда:

rm /srv/shared/student2_file.txt

Если основной пользователь не входит в группу developers, удаление завершается ошибкой Permission denied.

Причина заключается в том, что для удаления файла необходимы права записи и выполнения на каталоге. У остальных пользователей каталога /srv/shared имеются права r-x, поэтому они могут просматривать каталог, но не могут изменять его содержимое.

5. Чем su отличается от sudo
su используется для переключения на другого пользователя. Например:

su - student2

После выполнения команды текущая оболочка начинает работать от имени пользователя student2.

sudo используется для выполнения отдельной команды с повышенными правами, обычно от имени root.

Например:

sudo mkdir /srv/test

В этом случае не происходит постоянного переключения пользователя: повышенные права используются для выполнения конкретной команды.

Таким образом, su обычно используется для смены пользователя и получения его оболочки, а sudo — для выполнения отдельных команд с правами другого пользователя, чаще всего root.

6. Почему в Ubuntu по умолчанию заблокирован вход под root
В Ubuntu учетная запись root по умолчанию не используется для обычного интерактивного входа. Для административных действий используется sudo.

Такой подход позволяет выполнять административные операции через обычную учетную запись и не работать постоянно в оболочке root. Это уменьшает вероятность случайного выполнения опасных команд с максимальными правами.
